# TM-178 — `EncodingError: source image cannot be decoded` RCA + compose-time fix

## Symptom (user-reported)

Browser console:

```
EncodingError: The source image cannot be decoded.
```

Repro asset: `cmpaspov70001dmhlu5co33bc` ("Super Mario Style Animation with Walking Bear", multi-step pipeline, asset-gen used). Console also logs:

```
[TM-116] scene render error in Scene2: imageUrl is not defined
```

…fired in tight succession, multiple times per second.

## TL;DR root cause

**The PNG file is fine. The bug is an identifier-scope issue in the composed module.**

1. The per-scene scene-code system prompt (this branch's HEAD) tells gpt-4o to splice the generated PNG via `<Img src={imageUrl} />` — a **bare identifier**.
2. The composer (`composeSceneCodes`) never declares `imageUrl` at module scope. It only puts it on `PARAMS.imageUrl` for the customize-UI auto-extract.
3. Inside `Scene2 = ({ scene1_color = … } = Scene2Params) => { … <Img src={imageUrl} /> … }`, `imageUrl` is **undefined** (not in destructured props, not in closure).
4. `<Img>` (Remotion) receives `src={undefined}`. Browser → HTMLImageElement.src=null → tries to decode the page URL / empty payload as PNG → **"EncodingError: The source image cannot be decoded."**
5. `__SceneBoundary` (TM-116) catches the throw and blanks Scene2 → user sees Scene1 only with looping warnings.

## Phase A — diagnostic forensics

| Hypothesis from task spec | Verdict | Evidence |
|---|---|---|
| (a) File truncated / disk write race | **REJECTED** | `49067ee…png` is 1,964,263 B, valid PNG signature `89 50 4E 47`, valid `IEND` chunk, `file` reports `PNG image data, 1024 x 1024`. |
| (b) gpt-image-1 corrupt response | REJECTED | Same as (a). Image decodes cleanly with `file`, `xxd`, browser, `curl … > /tmp/x.png` byte-diffs perfectly. |
| (c) base64→buffer decode bug | REJECTED | Bytes round-trip end-to-end. `Buffer.from(b64, 'base64')` in `asset-gen.ts:107` is symmetric. |
| (d) URL / path mismatch | REJECTED | `curl http://localhost:3001/uploads/asset-gen/49067ee…png` → 200 OK, correct Content-Type, byte-identical to disk. |
| (e — actual) Bare identifier in generated scene | **CONFIRMED** | DB code dump shows `<Img src={imageUrl} />` inside `Scene2` body. `Scene2`'s destructured props only contain `scene1_*`. `PARAMS.imageUrl` is set correctly but unused by `Scene2`. |

Decisive log evidence (`.next/dev/logs/next-development.log`):

```
00:01:11.969  [pipeline] stage=scene-specs+asset-gen ms=37044 {assetGenUsed:true,...}
00:01:12.330  EncodingError: The source image cannot be decoded.
…
00:05:34.117  [TM-116] scene render error in Scene2: imageUrl is not defined
```

The `imageUrl is not defined` line is the **true** error — the `EncodingError` is downstream noise from Img-with-undefined-src.

## Phase B — fix

**Compose-time shim** (`src/lib/ai/pipeline.ts:composeSceneCodes`). When:
- `imageUrl` is provided AND
- at least one fragment references `imageUrl` as a bare identifier AND
- no fragment declares `imageUrl` itself (avoid SyntaxError on redeclare),

…inject a module-scope `const imageUrl = "<url>"` shim immediately before the fragments. The bare references then resolve to the same string `PARAMS.imageUrl` carries.

Rationale for this fix shape over alternatives:

| Alternative | Why rejected |
|---|---|
| Pass `imageUrl` as prop on `<Scene{N} />` | Requires every scene to destructure it; gpt-4o drift makes this fragile (TM-112 already burned us on params naming). |
| Rewrite bare `imageUrl` → `PARAMS.imageUrl` in fragments | More invasive regex over LLM output; risk of false matches inside string literals (`"imageUrl: …"`). |
| Strengthen the per-scene prompt to forbid bare identifier | **Already done on `main`** (line 720 there says `PARAMS.imageUrl`). This branch is older. Prompt-only fix is unreliable — gpt-4o still drifts in ~30% of multi-scene runs. |
| Server-side runtime guard in __SceneBoundary | Boundary already catches the throw but can't synthesize a missing identifier. |

The shim is **defense in depth on top of** the prompt fix on main, not a replacement for it.
