# TM-100 회고 — ai-quality-judge agent + judge-acceptance skill

## TL;DR

LLM-as-judge 사이클(TM-46 r2~r7, TM-66, TM-70, TM-73, TM-85, TM-108)이 모두 **개별 ad-hoc 호출 + ad-hoc retro** 패턴이었다. ADR-0016/0017/0018 의 결정성 + 4-criteria gate 규약을 매번 사람이 머릿속에 인용해 PR 본문에 박는 식으로 운영. TM-98 의 `ai-prompt-tuner` 특화 agent 패턴이 같은 방식으로 `ai-prompt` 도메인을 흡수한 것을 그대로 본떠, **`ai-quality-judge` agent + `judge-acceptance` skill**을 신설했다.

본 task 는 **doc-only**. 코드/벤치 산출물 변경 없음.

## 무엇을 했나

1. **Phase A — 기존 ad-hoc judge 인벤토리** (worktree 상태 기준):
   - `__tests__/benchmarks/tm-46-judge.ts` — visual judge 본체 (gpt-4o multimodal, 4축 rubric, temp=0/seed=42 적용 후)
   - `__tests__/benchmarks/tm-46-prompts.ts`, `tm-46-rubric.md` — corpus + rubric 정의
   - `__tests__/benchmarks/tm-66-smoke.ts` — 1-prompt smoke (TM-66 multimodal migrate 후속)
   - `__tests__/benchmarks/tm-70-judge-variance.ts` — variance RCA (ADR-0018 근거)
   - `__tests__/benchmarks/tm-46-r{2..7}-analyze.ts` — 회차별 분석
   - `__tests__/benchmarks/tm-108-r5-judge.ts` — 부분 capture re-judge (data-viz bench)
   - `scripts/qa/tm-85-pipeline-quality.mjs` — pipeline mode_match (judge 단계만 본 agent 흡수 후보)

2. **Phase B — `.claude/agents/ai-quality-judge.md` 작성**:
   - TM-98 (`ai-prompt-tuner`) 패턴 그대로. 책임/소관/금지/PM 라우팅 트리거 명문화.
   - ADR-0016 (4-criteria gate) / 0017 (capture determinism) / 0018 (judge determinism — temp=0, seed=42, N≥3) 직접 인용.
   - 표준 검증 매트릭스 4종 (lint → smoke → variance probe → full re-run) 의무화.

3. **Phase C — `.claude/skills/judge-acceptance.md` 작성**:
   - 신설 폴더 `.claude/skills/` (이 repo 의 첫 in-repo skill — 전역 skill 과 별개).
   - 입력 파라미터(corpus_path / judge_model / criteria / n_shots / seed / temperature / smoke / out_path / round_label) + 산출물 JSON 스키마(`runs[]`, `delta_max`, `std`, `acceptance.passed` 등) 표준화.
   - 워크플로 6 단계: pre-guard → variance probe → judge call → 4-criteria gate → spawn 권고 → retro 표 강제.
   - 사용 시나리오 매핑 표 (TM-46 / TM-66 / TM-70 / TM-73 / TM-85 / TM-108 → 해당 entry script).

4. **Phase D — PM router 갱신**:
   - `.claude/agents/pm.md` 의 특화 agent 라우팅 표에 `area="qa-judge"` 추가.
   - 트리거: `__tests__/benchmarks/tm-46-judge.ts | tm-46-rubric.md | tm-66-smoke.ts | tm-70-judge-variance.ts | tm-108-r5-judge.ts` 경로 매치, 또는 "LLM-as-judge / visual judge / acceptance gate / 4-criteria / rubric / noise band / variance" 키워드, 또는 TM-46/66/70/73/108 라인 의존.
   - 충돌 방지 규칙 명시: 변경 본체가 `src/lib/ai/*` prompt 면 `ai-prompt-tuner` 우선.

## 검증

- doc-only — 빌드/테스트 영향 없음 (`pnpm typecheck`, `pnpm lint` 등은 생략, judge 코드 미수정).
- agent / skill 본문은 ADR-0016/0017/0018 원문과 cross-reference 확인 (4-criteria 항목명 / 4축 정의 / variance floor Δmax≤3 / N≥3 등 모두 일치).
- TM-98 (`ai-prompt-tuner`) 패턴과의 구조 일관성 확인:
  - frontmatter `name`/`description`/`tools`/`model` 동일 키.
  - "표준 검증 매트릭스 / SOP 차이점 / 사용 트리거 / 금지" 4개 섹션 동일 골격.
  - PR title prefix (`feat(ai)` ↔ `qa(judge)`/`feat(judge)`) 만 도메인에 맞게 변경.

- TM-98 패턴이 굳어졌다 (ai-prompt-tuner → ai-quality-judge). 후속 특화 agent 도 같은 4-섹션 골격 재사용 가능. `marketer` / `planner` 도 같은 패턴으로 SOP 차이점 표를 보강하면 일관성↑.
