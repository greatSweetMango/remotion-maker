# TM-53 — extractJson repair ladder

## Context

TM-41 QA flagged `ld-07` (`Loading bar with percentage text "Loading 42%", dark theme`, FREE/`gpt-4o-mini`) as the lone "AI did not return valid JSON" failure across the loader benchmark (15 301 ms wall, `extractJson()` returned `null`). Hypothesis in the bug spec: `%` + nested unescaped `"` confused the JSON envelope.

When I re-ran the live call against `gpt-4o-mini` with the current prod config (`response_format: json_object`, `temperature=0`, `seed=42`) the model now returns clean JSON in 6.3 s — TM-69's json-mode enforcement already shut down the dominant failure mode after TM-41 was filed. So the immediate ld-07 reproduction is gone, but the underlying brittleness in `extractJson` (no trailing-comma tolerance, no smart-quote tolerance) remained as a one-line pothole waiting for the next variant.

## Change

`src/lib/ai/generate.ts` — `extractJson` now runs a four-step repair ladder:

1. raw `JSON.parse`
2. backtick-quoted string values → `"…"` (existing TM-41 path)
3. **NEW** `repairTrailingCommas` + `repairSmartQuotes`
4. all repairs combined

`repairTrailingCommas` is JSON-string-aware (won't touch commas inside `"..."`), so the `"hello, world,"` value above survives unscathed. `repairSmartQuotes` only touches the six curly-quote codepoints.

Both helpers are exported for unit-testing and to be reusable by `pipeline.ts:extractJsonObject` if a future task wants to lift them.

## Tests

`__tests__/lib/ai/generate.test.ts` — six new specs:

* `repairTrailingCommas` strips `,]` / `,}` but preserves intra-string commas
* `repairSmartQuotes` rewrites `“”‘’` → ASCII
* `extractJson` rescues trailing-comma payloads
* `extractJson` rescues smart-quote-corrupted payloads (ld-07 hypothesis)
* `extractJson` rescues combined backtick + comma + smart-quote payloads
* negative test: still returns `null` for genuine non-JSON text (no false rescue)
* integration: `generateAsset` end-to-end with a malformed ld-07-style payload now returns a `generate` response with `title: "Loading 42%"`

`npm test` → 651 passed, 13 skipped, 0 regressions. The 5 "FAIL" suites are the pre-existing visual-regression / perf infra files (not test files); confirmed identical failures on `HEAD~0`.

## Live verification

`gpt-4o-mini` + ld-07 prompt → parsed OK, 6.3 s, 1 479-char body. Current prod path no longer reproduces the original failure (TM-69 closed it). The repair ladder is now defense-in-depth for the next variant.
