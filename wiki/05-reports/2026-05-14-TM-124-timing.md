# TM-124 — Multi-step pipeline timing + visibility

## Why

User suspicion: "생성도 너무 빨리 된 거 아닌가" — could `/api/generate`
really be running the full TM-102 multi-step pipeline, or was it
silently taking the single-shot fast path? `AI_MULTI_STEP` is **off
by default** (gated behind an env flag), so unless the deployment
explicitly sets `AI_MULTI_STEP=1`, every request hits the single-shot
path. That alone matches the user's "too fast" report.

This task adds (a) per-stage wall-clock instrumentation to the
multi-step pipeline, (b) a `assetGenStages` metadata field on the
`/api/generate` response, and (c) a small dev badge in the studio that
proves at a glance which path ran.

## What changed

| Layer | File | Change |
|---|---|---|
| Types | `src/types/index.ts` | New `PipelineTiming` / `PipelineTimingStage`. Added optional `assetGenStages` to `GenerateApiResponse.generate`. |
| Pipeline | `src/lib/ai/pipeline.ts` | Per-stage timing capture in `generateAssetMultiStep`. Dev-only `console.warn` traces. Fallback path now also emits a `single-shot-fallback` timing. |
| Route | `src/app/api/generate/route.ts` | Synthesizes a `single-shot` timing when multi-step did not run; forwards `assetGenStages` to the client. |
| Client hook | `src/hooks/useStudio.ts` | Stores last `pipelineTiming`; exposes it to consumers. |
| Studio UI | `src/components/studio/PipelineTimingBadge.tsx` (new) + `Studio.tsx` mount | Always-on, click-to-expand HUD in the bottom-right of `/studio`. Shows mode, total seconds, stage breakdown. |
| Bench | `__tests__/benchmarks/tm-124-timing-bench.ts` | 5-prompt × 2-mode harness. Writes `__tests__/benchmarks/results/tm-124-timing.json`. |

Backward compatibility: `assetGenStages` is optional everywhere; old
clients ignore it.

## Live bench

5-prompt TM-46 smoke corpus, `gpt-4o`, two modes (AI_MULTI_STEP=1 vs 0).
Each prompt invoked once per mode → 10 OpenAI calls total.

| id | category | multi-step ms | scenes | single-shot ms | speed-up vs multi |
|---|---|---|---|---|---|
| dv-01 | data-viz   | 13 668 | 1 |  8 571 | 1.59× |
| ta-02 | text-anim  | 13 881 | 1 |  8 528 | 1.63× |
| tr-02 | transition | 11 742 | 1 |  4 469 | 2.63× |
| ld-01 | loader     | 14 398 | 1 |  5 171 | 2.78× |
| ig-01 | infographic| 18 479 | 1 |  9 972 | 1.85× |

**Aggregate** (mean of 5):
- multi-step: 14 434 ms, 5/5 ok, 0 asset-gen hits (no living-entity in this corpus)
- single-shot: 7 342 ms, 5/5 ok
- ratio: multi-step is **~2.0× slower** than single-shot on this corpus

Stage breakdown (mean across multi-step runs):
- outline:                  ~3.3 s
- scene-specs + asset-gen:  ~6.8 s (parallel; asset-gen no-op here)
- scene-code:               ~4.4 s
- compose + validate:       <5 ms

Raw runs: `__tests__/benchmarks/results/tm-124-timing.json`.

## Findings

1. **The "too fast" report is consistent with single-shot being the
   default.** In production today, `AI_MULTI_STEP` is unset → every
   `/api/generate` request currently takes the single-shot path
   (~5-10 s). The TM-102 pipeline scaffolding is built but not in the
   user's request flow.
2. **The pipeline does run end-to-end when enabled.** All 5 smoke
   prompts succeeded under `AI_MULTI_STEP=1`. Per-stage timing matches
   the architecture (outline → parallel(specs, asset-gen) → parallel
   scene-code → compose).
3. **Outline collapsed to 1 scene for every smoke prompt.** Even
   prompts that the rubric tags as multi-shot (infographic, transition)
   came back with a single scene. Worth a follow-up (TM-125?) to look
   at the outline system prompt — at minimum we should bench a "force
   ≥2 scenes" variant before we can claim multi-step is buying us the
   richer compositions ADR-0020 promised.
4. **Asset-gen never fired in this corpus** (no living-entity tokens
   in the 5 smoke prompts). The badge correctly shows `assetGenUsed=
   false`; the bench summary records 0 hits. Needs a separate run on
   TM-90's living-entity corpus to time the gpt-image-1 leg.

## How to verify

1. `cd worktrees/TM-124-pipeline-timing && AI_MULTI_STEP=1 npm run dev -- -p 3124`
2. Open `localhost:3124/studio`, enter any prompt, generate.
3. Bottom-right badge appears: `multi-step (N scenes) XX.YYs`.
4. Click to expand → per-stage ms list.
5. Restart dev server without the env flag — badge shows
   `single-shot ~5-10s` instead.

Re-run the bench any time with:
`npx tsx __tests__/benchmarks/tm-124-timing-bench.ts`
(~$0.20 in OpenAI spend per run).
