# TM-185 — "애니메이션이 안 움직인다" Class-A 잔여 원인 제거

한 줄 요약: Remotion 프레임-격리 렌더에서 t=0에 얼어붙는 CSS 애니메이션(@keyframes / transition / animation shorthand)을 sandbox에서 reject하고, GENERATION + SCENE_CODE system prompt에 frame-driven 강제 블록 + 검증된 few-shot 3종을 고정 배치했다.

## 배경 / 근본 원인

사용자 직접 보고: "애니메이션이 안 움직인다". RCA — `GENERATION_SYSTEM_PROMPT`는 `useCurrentFrame`/`interpolate`/`spring`를 가르치지만 **CSS 애니메이션을 금지하지 않았고**, `sandbox.ts`는 `setTimeout`/`setInterval`/`requestAnimationFrame`만 deny → CSS `transition`/`@keyframes`/`animation`은 통과. Remotion은 매 프레임을 격리 렌더(player가 프레임으로 seek 후 wall-clock 연속성 없이 새 DOM 페인트)하므로 wall-clock 기반 CSS 애니메이션은 t=0에 얼어붙는다(docs /flickering). 이것이 "안 움직이는" 출력의 Class A 잔여 원인.

## False-positive 정밀화 (정상 frame-driven 코드 절대 reject 금지)

- 정규식은 **CSS property key 형태**(`transition:` / `animation:`)에 앵커 — 식별자 `ZoomTransition`/`CounterAnimation`/`WebkitTransition`/지역변수 `const transition`은 매치 안 됨.
- `transition: 'none'` / `'0s'` / `transitionDuration: 0` (zero-duration)는 무해 → 허용. 양수 시간(`0.3s`/`200ms`)만 reject.
- bare `transitionProperty`(duration 없음, 기본 0s)는 inert → 허용.
- 35 템플릿 corpus 대상: 유일하게 `CounterAnimation`의 frozen transition만 트리거(같은 PR에서 제거) → FP 0.

## 캐시 안정성 (ADR-0003)

few-shot/anti-pattern 블록은 system prompt 고정 body에 배치, per-request 변동 없음. 추가 블록의 모든 `${...}`는 escape(`\${`/`\``)되어 리터럴 텍스트로 렌더 → cache key는 이 prompt-text 변경으로 **1회만** 무효화(의도된 동작, Lottie 카탈로그 선례와 동일). 매 요청 변동 없음.
