# TM-119 Retro — Per-task / per-model cost dashboard

> Extend TM-104 weekly roll-up with cost breakdowns sourced from the TM-112
> `spend-ledger.jsonl`. Goal: see which tasks and which models drive spend.

## What shipped

- `scripts/dashboard/roll-up.mjs` — `collectSpend()` now aggregates the ledger
  three ways in addition to the previous `by_kind` total:
  - **Per-task** (`task_id` → cost, calls, tokens_in, tokens_out), sorted desc,
    surfaced as top-10.
  - **Per-model** (`model` → cost, calls, tokens), sorted desc, top-10.
  - **Daily trend** (YYYY-MM-DD → cost), chronological, for spend cadence.
- Markdown renderer adds three new tables under `## Spend`:
  - `### Per-task cost (last Nd, top 10)`
  - `### Per-model cost (last Nd, top 10)`
  - `### Daily spend trend (last Nd)`
- `.agent-state/dashboard.json` snapshot now contains
  `spend.ledger_by_task`, `spend.ledger_by_model`, `spend.ledger_daily`
  arrays — downstream consumers (alerts / KPIs) can read raw numbers.
- Empty/missing ledger degrades gracefully ("no per-X spend in window") —
  same convention as the existing bench rollup.

## Schema confirmed (TM-112)

`.agent-state/spend-ledger.jsonl`, JSONL append-only, one object per
provider call from `.claude/hooks/post-tool-use.sh`:

```
{ ts, task_id, model, tokens_in, tokens_out, cost_usd, kind }
```

`kind ∈ {openai, anthropic, other}`. `task_id` falls back to `unknown`
when `CLAUDE_TASK_ID` env / `.agent-state/current-task` file are both
absent (TM-117).

## Verification

1. `node scripts/dashboard/roll-up.mjs --dry-run` on a clean tree —
   new sections render `_(no per-X spend in window)_`. No errors.
2. Seeded a 60-row synthetic ledger across 6 tasks × 5 models × 7 days
   and re-ran `--dry-run`. Tables sorted by cost desc, totals match
   `ledger_window_total_usd` to 4 decimals (e.g. $13.9750 == Σ rows).
3. Removed synthetic seed and ran `node scripts/dashboard/roll-up.mjs`
   for real artifacts:
   - `wiki/02-dev/dashboard.md` overwritten — new sections present.
   - `.agent-state/dashboard.json` overwritten with the three new arrays.
   - stdout: `window=7d merges=55 benches=4 avg_mode_match=92.1`.

## Decisions / non-goals

- No new dependencies. Stayed zero-dep ESM, consistent with the original
  TM-104 design constraint.
- No ASCII sparkline / chart in markdown — Obsidian-side mermaid is a
  follow-up if anyone actually reads the trend visually.
- Top-N capped at 10 to keep the markdown readable; full data lives in
  `.agent-state/dashboard.json` for programmatic use.
- Did not change cost-burst guard (`scripts/orchestrator/stop-guard.mjs`).
  That reads the ledger directly with its own window logic — they share
  the schema only.
