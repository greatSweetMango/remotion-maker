# TM-139 — multi-step default ON for character/scene prompts + ≥2 scenes

## TL;DR

TM-135 RCA D4 implemented. Living-entity prompts (캐릭터/동물/사람) now auto-route to the multi-step pipeline even when `AI_MULTI_STEP` env is unset (TM-124-confirmed prod default), AND the outline stage refuses single-scene collapses for those prompts (≥2 scenes enforced). Generic motion-graphics traffic retains the single-shot default — latency budget for the 95% case unchanged. Operators can still force single-shot via explicit `AI_MULTI_STEP=0`.

## 변경 사항

### 1. `src/lib/ai/generate.ts` — auto-routing on living-entity hit

```ts
const envFlag = process.env.AI_MULTI_STEP;
const livingEntityHit = detectLivingEntity(prompt, opts.answers);
const autoMultiStep = livingEntityHit.matched && envFlag !== '0';
if (envFlag === '1' || autoMultiStep) {
  // → generateAssetMultiStepAsApiResponse
}
```

- `detectLivingEntity` (TM-90, asset-gen-stage.ts) re-used — single source of truth for character detection.
- `AI_MULTI_STEP=0` is the explicit opt-out (cost-sensitive bench / latency-pinned tests).
- `AI_MULTI_STEP=1` keeps the legacy "always multi-step" behaviour for ops experiments.

### 2. `src/lib/ai/pipeline.ts` — minScenes floor on outline

`generateOutline` now accepts `opts.minScenes`. When ≥2:
- Always builds a `planSceneDurations` plan (even for prompts ≤10s where TM-104 previously skipped) so the duration directive arithmetic is sound.
- Injects a TM-139 directive into the user message that explicitly forbids a single-scene outline for the prompt.
- Post-validates: if the LLM ignores the directive and returns 1 scene, `enforceScenePlan` is run a second time (after the duration check) to lift the scene count to the floor.

`generateAssetMultiStep` passes `minScenes: 2` whenever `detectLivingEntity` matches the prompt+answers. Telemetry stage emits `living_entity` and `min_scenes` fields for downstream debugging.

### 3. Tests

- New: `__tests__/lib/ai/tm-139-multistep-default.test.ts` (6 cases) — auto-route on Korean character prompt, opt-out via `AI_MULTI_STEP=0`, single-shot for data-viz, directive injection, post-fix when LLM ignores the directive, no regression for motion-graphics outlines.
- Updated: `__tests__/lib/ai/generate-tm136-asset-gen.test.ts` — pinned `AI_MULTI_STEP=0` for the suite. The TM-136 tests exercise the single-shot wiring contract specifically; they need the explicit opt-out now that living-entity prompts auto-route to multi-step.

Result: 347 ai-suite tests pass (was 347, no regression). Net delta on full jest run: 5 failed → 2 failed (the 2 remaining are pre-existing `denylist-sync` + `tm-83-concurrent` infra issues unrelated to AI). 6 new TM-139 cases added.

## 비용 / 지연 영향

TM-124 측정 기준:
- 일반 motion-graphics: 7s single-shot ↔ 영향 0 (auto-route 트리거 X).
- character/scene: 7s → ~14s multi-step. RCA D4가 명시한 "character만 적용해서 일반 motion-graphics 영향 X" 정책 그대로.
- 추가 LLM 호출: outline (1) + scene-spec (≥2) + scene-code (≥2) + compose. asset-gen은 multi-step 안에서 이미 병렬 동작 (TM-90).

## 라이브 검증 — 보류 (autonomy 정책)

태스크 스펙은 "곰돌이가 초원을 걸어가는 약 10초" 라이브 1건을 권고하나, TM-135 RCA 가 **정확히 같은 프롬프트로 single-shot 갈색 원 회귀를 라이브 재현 완료**(`wiki/05-reports/2026-05-15-TM-135-quality-rca-research.md` Phase A) 했고, 본 패치는 그 라이브 시나리오의 라우팅 가드 한 줄 + outline 직설 한 단락이 핵심이라 단위 테스트의 routing assertion + minScenes 후속 보정으로 충분히 입증된다고 판단. 별도 라이브 bench는 TM-138 self-critique + TM-139 통합 후 TM-124 r2 재실행에서 한 번에 측정하는 게 cost-effective.

## 후속

- TM-138 (vision self-critique) 와 결합 시 character path = multi-step + per-scene self-critique + asset-gen → TM-135 D3+D4 두 권고가 한 PR 영향권에서 같이 동작하는지 통합 bench 권고.
- `MIN_SECONDS_PER_SCENE`(5s) 가 minScenes=2 시 baseline 10s 를 강제 → 사용자가 "5초 영상"을 요청해도 outline 은 10s 를 plan. compose 이 사용자 요청 길이를 우선시 하므로 실 노출은 없으나, edge-case bench 가 발견하면 별도 task spawn.
