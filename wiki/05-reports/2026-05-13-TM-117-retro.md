# TM-117 — Wire CLAUDE_TASK_ID env to Orchestrator/TeamLead

## 문제

`spend-ledger.jsonl` (TM-112 producer, TM-101 schema) 가 매 LLM 호출마다 `task_id` 를 기록하지만, TeamLead 서브에이전트 세션에서는 `CLAUDE_TASK_ID` env 가 주입되지 않고 `.agent-state/current-task` 파일도 비어 있는 경우가 잦아 대부분 라인이 `"unknown"` 으로 떨어졌다. 그 결과:

- stop-guard `cost_burst` 신호가 task 별 attribution 불가 → 어떤 task 가 비용을 폭발시켰는지 retro 시 추적 곤란.
- `error_rate_spike` 와 task 단위 cost regression 분석이 동작하지 않음.

## 사실 확인

`.claude/hooks/post-tool-use.sh` 의 fallback chain 은 이미 올바르다:

```bash
task_id="${CLAUDE_TASK_ID:-}"
if [[ -z "$task_id" && -f "$CURRENT_TASK_FILE" ]]; then
  task_id="$(head -n1 "$CURRENT_TASK_FILE" 2>/dev/null | tr -d '[:space:]' || true)"
fi
[[ -z "$task_id" ]] && task_id="unknown"
```

즉 hook 수정은 불필요. **wiring 누락만 문제**.

## 변경

1. `scripts/orchestrator/set-current-task.sh` (신규, idempotent helper)
   - `TM-N` 또는 bare `N` 입력 정규화, `git rev-parse --show-toplevel` 로 워크트리 안전 처리.
   - `.agent-state/current-task` 한 줄 덮어쓰기.
2. `prompts/team-lead.md` — Phase A0 추가
   - TeamLead 첫 Bash turn 의무 호출: `bash scripts/orchestrator/set-current-task.sh TM-{task_id}`.
   - 헬퍼 없을 때 fallback (`mkdir -p .agent-state && echo "TM-{id}" > .agent-state/current-task`).
3. `.claude/commands/orchestrate.md` Step 4 — TeamLead Agent prompt 에 wiring 지시문 명시 + Orchestrator 본인 세션도 매 iter 시 helper 호출 권고.

## 검증

3-tier fallback 모두 라이브 hook 으로 확인 (test ledger lines 사후 cleanup):

| 시나리오 | 입력 | 결과 |
|---|---|---|
| env 우선 | `CLAUDE_TASK_ID=TM-999` + file=`TM-117` | `task_id="TM-999"` ✓ |
| file fallback | env unset + file=`TM-117` | `task_id="TM-117"` ✓ |
| unknown | env unset + file 없음 | `task_id="unknown"` ✓ |

helper 단위 테스트:

- `set-current-task.sh 117` → writes `TM-117` ✓
- `set-current-task.sh TM-117` → writes `TM-117` ✓
- `set-current-task.sh bad-id` → exit 65, stderr usage ✓

## 회귀 방지

- TeamLead prompt Phase A0 가 의무 단계로 박혀있어 누락 시 첫 turn 에서 즉시 드러남.
- Orchestrator Step 4 prompt template 에 wiring 지시 인라인 — 향후 prompt 변경 시 PR review 가 강제됨.
- 워크트리별 `.agent-state/current-task` 가 격리되므로 병렬 TeamLead race 없음.
