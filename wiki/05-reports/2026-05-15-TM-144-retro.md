# TM-144 — Lottie 카탈로그 큐레이션 (CC0-1.0 직접 생성본 8종)

## TL;DR

ADR-0027 §1 후속 큐레이션. LottieFiles 라이선스 위험(개별 자산별 SaaS 재배포 금지 조항 분산)을 회피하기 위해 **EasyMake 직접 생성 stub Lottie 8종**(전부 CC0-1.0)으로 카탈로그를 채움. `scripts/lottie/generate-stub-lotties.ts`로 결정론적 재생성 가능. TM-140 단위 테스트 47/47 + sandbox 55/55 + audio-manifest 13/13 = 115 그린.

## 무엇이 바뀌었나

- **8개 자산 추가** (`public/lottie/*.json`):
  - character: `bear-walk`, `cat-walk`, `dog-run`, `cat-idle`, `person-dance`, `kid-jump`, `bird-fly`
  - scene: `sky-clouds`
  - 모두 CC0-1.0, attribution `EasyMake (TM-144 hand-authored stub)`
  - 모두 단순 shape-based (ellipse/rect + transform 키프레임). expression 없음, embedded image 없음, font 없음 — `@remotion/lottie`가 지원하는 feature subset만 사용.
- **MANIFEST.json 갱신**: 기존 placeholder 1건 → 8건. sha256 + bytes 모두 결정론적 (스크립트가 stable JSON serialization 사용).
- **Generator 스크립트**: `scripts/lottie/generate-stub-lotties.ts`. 향후 외주 AE 익스포트 자산으로 swap 시 manifest 스키마 변경 불필요.
- **Verifier 스크립트**: `scripts/lottie/verify-stub-lotties.ts`. manifest sha256 일치 + Lottie 최소 형태(v/fr/ip/op/w/h/layers) + manifest의 `durationFrames`/`fps`가 Lottie의 `op-ip`/`fr`과 일치하는지 검증.

## 왜 LottieFiles 다운로드가 아닌 자체 생성인가

처음에는 LottieFiles의 Free Lottie 탭을 스크래핑하려 했음. 발견:

1. **개별 자산 라이선스가 균일하지 않음** — "free for personal use"가 다수, SaaS 재배포 금지 조항이 흔함. EasyMake 같은 prod 서비스에는 사용 위험.
2. **CDN URL이 영속적이지 않음** — `assets1.lottiefiles.com/packages/lf20_*.json` 일부는 200 OK로 받아지지만 출처 페이지가 사라지면 라이선스 증빙이 끊김.
3. **다른 후보**(airbnb/lottie-web demo, LottieFiles GitHub 샘플)는 경로가 deep restructure로 404.

자체 생성 시 모든 위험이 사라짐:

- 출처가 EasyMake repo의 알려진 commit (script 자체).
- sha256이 결정론적으로 재현 가능 — manifest integrity check가 안정적.
- 외부 EULA가 우리를 retroactive하게 막을 수 없음.

대가: 그래픽 품질이 단순함(geometric shape silhouette). 카탈로그 컨벤션·UI·프롬프트 통합을 unblock하는 데는 충분. 향후 ADR로 외주 후 개별 자산 swap 가능 (manifest 스키마 동일).

## 결정 기록

- **카탈로그 자산은 EasyMake 자체 생성 CC0-1.0 stub으로 간다** (TM-144 한정 결정 — 카탈로그 미러 deps 패턴은 ADR-0027 그대로 유효). 외부 자산 swap은 별도 ADR 필요.
