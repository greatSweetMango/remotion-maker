# TM-182 retro — 빈(검은/흰) 영상이 비정상적으로 빠르게 생성

> User-blocking incident: 프롬프트 "곰돌이가 초원을 걸어가는 10초 횡스크롤 애니메이션" →
> 정상 multi-step(30~90초 + asset-gen PNG) 대신 **빈 영상이 빠르게** 생성.
> RESUME 작업 (16일 전 중단된 미커밋 작업 이어받음).

## 1. 확정된 근본원인 (root cause)

**multi-step → single-shot fallback 경로가 asset-gen PNG를 통째로 드롭** (가설 #1 확정).

`pipeline.ts:generateAssetMultiStepAsApiResponse` 의 TM-111 fallback (sandbox/transpile 실패 시)이
`generateAsset(prompt, model)` 을 **answers 없이** 호출했다. single-shot 경로의 `eligibleForAssetGen`
게이트(TM-136)는 `answers` 가 있어야만 asset-gen을 발화한다(round-1 clarify에서 $0.04 낭비 방지).
fallback은 이미 generate 결정을 통과한 상태인데도 answers를 전달하지 않아 → **PNG 미생성 → `<Img>`
없는 vector-only(종종 빈) "곰돌이 walking" 씬을 빠르게 서빙** = TM-182 fingerprint.

추가로, fallback PNG를 못 만들거나 LLM이 구조적으로는 valid하지만 **아무것도 그리지 않는** 씬을
내놓아도 이를 감지하는 게이트가 없었다 → silent blank. 기존 `detectPlaceholderCode`(TM-51)는
*구조적* 스텁(too short / PARAMS 없음 / `() => null` / skeleton 주석)만 잡고, "길고 PARAMS 있고
AbsoluteFill 있지만 paint 0" 케이스는 통과시킨다.

## 2. 수정 (2-layer)

| Layer | 후보 | 변경 | 파일 |
|---|---|---|---|
| A. PNG 보존 | (A) | fallback 진입 시 living-entity면 `answers` 전달 + `forceAssetGen:true` 로 asset-gen 강제. 절대 wasted spend 아님(이미 generate 커밋됨). `asset_gen_used`/warning을 timing에 surface. | `pipeline.ts`, `generate.ts` (`forceAssetGen` opt) |
| D. silent blank 차단 | (D) | `detectEmptyComposition()` 신규 — `<Img>`/`PARAMS.imageUrl` 도 없고 visible leaf primitive(div/svg/text/...)도 없는 "container-wrapper-only" 씬을 감지. `detectPlaceholderCode` 와 **같은 placeholder retry 경로로 폴딩** → 재시도→strict재시도→known-good fallback template(visible, warning 동반) 또는 throw. **절대 silent blank 없음.** | `generate.ts` |

정밀도 우선: thin-but-legit 씬(transparent fill + 단일 animated `<div>`, data-viz svg/rect)은 통과.
오직 진짜 paint-empty(leaf primitive 0 AND Img 0 AND imageUrl 0)일 때만 발화.
