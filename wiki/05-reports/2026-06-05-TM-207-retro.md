# TM-207 — Fail-fast preflight guardrail

## TL;DR

Added a cheap, dependency-free `preflight.sh` the Orchestrator runs just before
dispatching a TeamLead — converts the "mystery 600s death" (unbootstrapped
worktree / port mismatch / missing key) into an immediate `blocked: <reason>`.
Additive only; loop/STOP guards untouched. 10/10 unit tests pass.

## 무엇이 바뀌었나

- New `scripts/orchestrator/preflight.sh <worktree_path> <dev_port> [--require-live]`:
  - env-only (always): `.env.local` exists, `NEXTAUTH_URL` port == `dev_port`,
    generated Prisma client resolvable.
  - `--require-live` only: required API keys present (default `OPENAI_API_KEY`,
    overridable via `PREFLIGHT_REQUIRED_KEYS`) + dev-server reachable via 3s curl.
  - JSON output `{ok,missing,reason}`; exit 0 pass / 20 fail / 64 usage.
- New `scripts/tests/test-preflight.sh` — 10 cases, all green.
- `.claude/commands/orchestrate.md` **Step 3 only** (~7 lines): call preflight
  pre-dispatch; on exit 20 → `branch-locks.sh set-status <id> blocked` + skip.
- ADR `ADR-0031`.

## 왜 / 배경

TeamLeads dispatched to a half-bootstrapped worktree or a live task with no key
/ no dev server didn't fail fast — they burned minutes + tokens, then died
opaquely (or hit a ~600s watchdog). OpenAI Swarm's *input guardrail* pattern:
validate agent inputs before paying for the run.

## 영향

- 코드/시스템: bad dispatches now blocked with machine-readable `missing[]`
  codes; future automation can auto-rerun `setup-worktree.sh` on
  `PRISMA_CLIENT_MISSING`. No new deps.
- 안전: additive — failure only marks the task `blocked`; Ralph loop / STOP
  unchanged. Default env-only run passes in key-less environments (load-bearing).

## 검증

`bash scripts/tests/test-preflight.sh` → all 14 assertions pass. Acceptance:
- env 누락(NEXTAUTH_URL 포트 불일치) → exit 20 + `NEXTAUTH_URL_PORT_MISMATCH`. ✓
- env 충족(키 없는 환경) → `--require-live` 없이 exit 0. ✓
- `--require-live` 키/포트 누락 → 정확한 reason (`KEY_MISSING:OPENAI_API_KEY`,
  `DEV_SERVER_UNREACHABLE`). ✓
