# TM-180 — @remotion/lottie version pin retro

## Problem

`@remotion/lottie@^4.0.461` pulled in `remotion@4.0.461` as a peer/transitive dep while the rest of the `@remotion/*` family (bundler, cli, player, renderer, core) was pinned to `^4.0.448`. Remotion **requires a single, matching minor version across all packages**; the mismatch caused dev/build 500 on every route once the Lottie code path was touched.

## Root cause

`package.json` carried `"@remotion/lottie": "^4.0.461"` (drift from a previous bump) while everything else stayed at `^4.0.448`. Lockfile shows two distinct `remotion` resolutions — one under Lottie's tree (`4.0.461`), one for the app (`4.0.448`).

## Fix

**Option (a) chosen** — pin Lottie down to the rest of the family rather than bumping the world up:

```diff
- "@remotion/lottie": "^4.0.461",
+ "@remotion/lottie": "^4.0.448",
```

Single `npm install @remotion/lottie@4.0.448` — minimal blast radius, zero risk of bumping other Remotion-coupled features.

**Lockfile diff**: removed the duplicate `remotion@4.0.461` install. Now a single `remotion@4.0.448` graph.

## Bonus (incidental) — tsconfig exclude `wiki`

Build was blocked by a second, pre-existing issue from TM-166: documentation snapshot tsx files under `wiki/05-reports/screenshots/TM-166/asset-code.tsx` were swept into the `**/*.tsx` include glob. They're loose snippets (no imports) so 84 TS errors / 26 lint errors fired during `next build`. Added `"wiki"` to `tsconfig.json#exclude` — minimal change to unblock Phase C build verification. (`wiki/` is documentation, not code; should never have been compiled.)

## Gotcha for tech-notes

Remotion 4.x **demands lockstep minor versions across `remotion`, `@remotion/bundler`, `@remotion/cli`, `@remotion/lottie`, `@remotion/player`, `@remotion/renderer`**. Any `^` caret drift between sibling packages = silent dev/build 500 once the off-version code path executes. When bumping any single `@remotion/*`, bump all of them in the same commit.
