# TM-132 retro — `<CatalogueAudio>` wrapper unblocks PARAMS-driven BGM swap

## TL;DR

The TM-130 BGM picker shipped but did nothing at runtime: the TM-128
sandbox forces `<Audio src={staticFile("audio/<literal>.mp3")} />`, and
the picker mutated `PARAMS.bgmTrack` which the literal `src` ignores.
TM-132 introduces `<CatalogueAudio track={bgmTrack} volume={...} />` —
a thin wrapper injected into the evaluator scope that accepts a
PARAMS-bound `track` prop, validates the shape (mirrors the catalogue
regex + traversal guard), and emits the literal `<Audio>` Remotion
expects internally. ADR-0026 amended with §B.

## Context

- TM-127: catalogue manifest + stub fixtures — shipped
- TM-128: sandbox `<Audio>` structural allow-list — shipped
- TM-129: edit prompt updated to teach the literal shape — shipped
- TM-130: BGM picker (Customize tab) + preview — shipped UI, broken runtime
- TM-131: Lambda export bundles `public/audio/` — shipped
- TM-132 (this work): make the picker actually swap tracks

The five spawn tasks ADR-0026 enumerated all individually passed their
own acceptance, but the integration story (picker → live audio swap)
was untested across them. Discovered when the user tried a track swap
and heard no change.

## Decision (Option B)

Compared three options:

| Option | Pros | Cons | Picked |
|---|---|---|---|
| A — sandbox allows `staticFile(PARAMS.<key>)` | smallest prompt change | enlarges sandbox surface; needs static-analyzer-grade source validation | no |
| **B — `<CatalogueAudio>` wrapper** | sandbox stays narrow (regex unchanged), picker UX clean, runtime guard handles malformed PARAMS | one new component to maintain | **yes** |
| C — LLM re-edit on swap | works mechanically | 2-5s latency, breaks ADR-0023, burns spend | no |

Rationale full text: `wiki/01-pm/decisions/0026-audio-policy.md` §B.

## Why this is safer than option A

The path-traversal worry mentioned in the spec ("user puts
`../etc/passwd` in PARAMS") is fully handled at the wrapper layer:

- `isValidCatalogTrack` rejects any string with `..`, `/` (after the
  optional `audio/` prefix), `\`, or that doesn't match
  `^[a-z0-9-]+\.mp3$`.
- Even if a hostile value sneaks past the predicate, `staticFile()`
  resolves relative to `public/`, so the worst case is a 404 on a
  static asset — never a server-side file leak.
- The Remotion `<Audio>` runtime requires a string `src`; the wrapper
  only ever passes a string built from a regex-validated slug.

## Follow-ups (none required, observations only)

- **Membership check:** the wrapper enforces shape, not catalogue
  membership. A non-catalogue but shape-valid filename (`fake.mp3`)
  would silently 404 at staticFile resolution. This is intentional —
  membership lives in the picker UI + LLM prompt; runtime stays sync
  + side-effect-free. If we ever surface a "catalogue out-of-sync"
  error toast in the studio, that's the place.
- **Edit-prompt cache:** the `EDIT_SYSTEM_PROMPT` was not modified;
  cache key stable (ADR-0003).
- **TM-115 denylist sync:** unchanged — only comments touched in the
  plugin mirror.
