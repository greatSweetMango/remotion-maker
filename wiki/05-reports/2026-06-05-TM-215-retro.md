# TM-215 — untrack `.agent-state/current-task` runtime anchor

## What & why
`scripts/orchestrator/set-current-task.sh` rewrites `.agent-state/current-task`
on every TeamLead dispatch. The file was git-tracked, so it landed in every
TeamLead commit/PR and collided across concurrent branches — **3 merge
conflicts + 1 pull abort** in orchestrator-v2 wave1.

## Change
- Added `.agent-state/current-task` to `.gitignore`, in the existing
  runtime-anchor block (next to `loop-count`, `STOP`, `.tasks.lock`,
  `.tasks.mutex.d/`).
- `git rm --cached .agent-state/current-task` — untracked, working-tree copy
  preserved.

## Conservative scope
Confirmed via `git log` that the remaining tracked `.agent-state` files are
intentional state/history and left them alone:
`branch-locks.json`, `spend.json`, `refactor-cron.json`, `concurrency-limit`,
`README.md`, `fuzz-results/*`. Only `current-task` (churned by orchestrator
commits TM-209/207/204) is genuinely ephemeral.

Did **not** touch `team-lead.md` / `orchestrate.md` / scripts — those are being
edited by concurrent wave tasks (TM-205), and `.gitignore` + `git rm --cached`
fully solves the problem on its own.

## Acceptance
- `git ls-files .agent-state/current-task` → empty (untracked). ✅
- `.gitignore` entry added; working-tree file preserved (`TM-215`). ✅
- Other tracked `.agent-state` files unchanged. ✅

## Takeaway
Any path a script rewrites per-run must be gitignored from the start. Worth a
quick audit of other orchestrator runtime writes if conflicts recur.
