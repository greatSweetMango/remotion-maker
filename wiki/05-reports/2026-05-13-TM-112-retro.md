# TM-112 — PostToolUse hook spend-ledger appender

## 배경

TM-101 은 `.agent-state/spend-ledger.jsonl` 의 포맷을 정의하고 **컨슈머**(`scripts/orchestrator/stop-guard.mjs` 의 `checkCostBurst`)만 구현했다. **생산자**가 비어 있어 `cost_burst` STOP 신호가 영원히 0 으로 평가되는 상태였다 — 야간 폭주 감지 가드가 사실상 무력. TM-112 가 이 갭을 메운다.

## 변경

### `.claude/hooks/post-tool-use.sh` 확장

기존 hook 은 `spend.json` 누적값만 갱신했다. 이번 PR 은 동일 페이로드에서 추출한 토큰/비용 데이터를 **두 번째 sink**(JSONL ledger)에도 append.

```jsonl
{"ts":"2026-05-13T03:21:18.000Z","task_id":"TM-112","model":"gpt-4o-mini",
 "tokens_in":4123,"tokens_out":812,"cost_usd":0.0024,"kind":"openai"}
```

핵심 결정:
- **포맷**: TM-101 README 스펙 그대로 — 7 키 (`ts task_id model tokens_in tokens_out cost_usd kind`)
- **kind 매핑**: 기존 hook 의 `provider` 변수 재사용 → `anthropic` | `openai` | `other`
- **task_id 해결 순서**:
  1. `CLAUDE_TASK_ID` 환경변수 (Orchestrator/TeamLead 가 명시적으로 export)
  2. `.agent-state/current-task` 파일 첫 줄
  3. `"unknown"` (둘 다 없을 때 — sandbox/CLI 호출)
- **동시성**: 별도 `.agent-state/.spend-ledger.lock` 으로 `flock` 직렬화 (기존 `.spend.lock` 과 분리 — append vs read-modify-write 가 충돌 없게)
- **실패 격리**: jq 누락이나 페이로드 파싱 실패 시 무음 통과 (`set -uo pipefail` + `|| true`) — hook 이 도구 흐름을 절대 막지 않음

### 테스트

`scripts/tests/test-spend-ledger-hook.sh` — 21 assertions, 6 케이스:

| Case | 검증 |
|---|---|
| 1 | Anthropic Sonnet 응답 → 1 줄, kind=anthropic, cost = (1000×3 + 200×15)/1e6 = 0.006 |
| 2 | OpenAI gpt-4o 응답 → 1 줄, kind=openai, cost = (2000×2.5 + 500×10)/1e6 = 0.01 |
| 3 | usage 블록 없는 페이로드 → ledger 생성 안 함 |
| 4a | `CLAUDE_TASK_ID` env 가 `current-task` 파일을 이긴다 |
| 4b | env 없으면 `current-task` 파일 사용 |
| 4c | 둘 다 없으면 `"unknown"` |
| 5 | 7 필드 스키마 완전성 + ISO-8601 ts 포맷 |
| 6 | 연속 2 호출 → 2 줄 (append-only) |

격리: 각 케이스는 임시 sandbox 에 hook 복사 + 자체 `.agent-state/` 시드 → 실제 ledger 오염 방지.

### 라이브 sanity

```bash
echo '{"tool_response":{"model":"gpt-4o-mini","usage":{"prompt_tokens":1234,"completion_tokens":56}}}' \
  | CLAUDE_TASK_ID=TM-112-sanity bash .claude/hooks/post-tool-use.sh

# → .agent-state/spend-ledger.jsonl 에 1 줄:
# {"ts":"2026-05-13T16:42:37.000Z","task_id":"TM-112-sanity","model":"gpt-4o-mini",
#  "tokens_in":1234,"tokens_out":56,"cost_usd":0.000219,"kind":"openai"}
```

이어서 stop-guard 와 end-to-end 검증 — sandbox 에 $3.5 짜리 ledger 한 줄 주입 후 `node scripts/orchestrator/stop-guard.mjs --json --dry-run`:

```
[stop-guard] cost_burst: OpenAI/LLM spend $3.50 in last 60min ≥ $3
{"ok":false,"fired":[{"signal":"cost_burst",...}],...}
```

→ **cost_burst 신호가 처음으로 실제 데이터 위에서 발화** 확인.

## 후속 권고

1. **current-task wiring 자동화** (별도 task 추천): Orchestrator/TeamLead 가 task delegation 시 `export CLAUDE_TASK_ID=TM-X` 또는 `echo TM-X > .agent-state/current-task` 하도록 `.claude/commands/orchestrate.md` 와 `prompts/team-lead.md` 업데이트. 현재 미연결 — ledger 의 `task_id` 가 대부분 `"unknown"` 으로 찍힐 가능성. TM-112 본문에는 hook 측 fallback 만 구현.
2. **dashboard 통합** (TM-104 follow-up): weekly roll-up 스크립트가 `spend-ledger.jsonl` 을 task/model breakdown 으로 집계하도록 확장.
3. **ledger 회전 정책**: 무한 append → 파일 크기 증가. 30 일 이상 데이터는 `spend-ledger.archive.YYYY-MM.jsonl.gz` 로 회전하는 cron 검토.
