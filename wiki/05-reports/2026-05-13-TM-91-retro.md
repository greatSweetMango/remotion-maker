# TM-91 — image-gen latency progressive UX (30s+)

## 요약

TM-84 벤치 결과 `gpt-image-1` p50 latency ≈ 38s. 기존 TM-88 Regenerate 다이얼로그는 38초 내내 단일 spinner + "Generating…" 한 줄 — 사용자가 작업이 멈춘 건지 진행 중인지 판단 불가. 본 PR 은 **순수 UI 변경** 으로 (1) 5/15/30 초 임계점에서 한국어 단계 메시지 전환 (2) 로지스틱 곡선 기반 Progress bar 가 p50≈38s 에서 약 74% 까지 도달하고 95% 에서 asymptote (3) 경과 초 카운터를 추가했다. 백엔드/모델 호출은 그대로.

## 변경

- `src/components/studio/ParameterControl.tsx`
  - import: `Progress`
  - `RegenerateImageButton` 에 `elapsedMs` state + 500ms interval (submitting 동안만 등록, cleanup 보장)
  - 다이얼로그 본문에 `<Progress>` + 단계 메시지 + 경과 초 표시 (`role="status"`, `aria-live="polite"`)
  - DialogDescription 에 "보통 30~40초 소요됩니다" 기대치 setting
  - 헬퍼 `progressMessage(ms)` / `progressPercent(ms)` 를 export — 순수 함수, 단위 테스트로 회귀 박제
- `__tests__/components/tm91-regen-progress.test.ts` (신규, 8 cases / 8 pass)

## 단계 메시지

| 경과 | 카피 |
|---|---|
| 0–5s | 이미지 생성 중… |
| 5–15s | AI가 그리는 중… (수 초 더 소요됩니다) |
| 15–30s | 고품질 렌더 진행 중… |
| 30s+ | 마무리 단계입니다… 거의 다 됐어요. |

## Progress curve

`progress = min(95, (1 - exp(-s/28)) * 100)` — 19s ≈ 50%, 38s(p50) ≈ 74%, 65s ≈ 90%. 95% cap → 진짜 응답 도착 시점이 discrete event 로 인지된다. TM-92 가 모델 latency 를 줄이면 `k=28` 상수만 재조정.

- **Pro tier 백그라운드 큐** — 사용자가 다른 작업하다 완료 알림 받는 패턴. UI/백엔드/notification 채널 모두 손대야 해서 별도 task 권장 (`spawn` 후속). 본 PR 단일 책임 유지.

## 알게 된 것

- 이 코드베이스는 `react-hooks/set-state-in-effect` 룰을 강제 → 효과 본문에서 reset 패턴 사용 불가. `onSubmit` 진입 시 `setElapsedMs(0)` 으로 옮기는 게 관용 패턴 (TM-90/91 housekeeping note 가 이미 동일 패턴 코멘트).
- `Progress` Radix wrapper 가 이미 존재 (`src/components/ui/progress.tsx`), `value` prop 만 넘기면 됨.
- 다이얼로그 본문은 textarea(5 rows) + (조건부) error + (조건부) progress block 으로 구성 — submitting 토글 시 높이 ~32px 증가하지만 자연스러움.
