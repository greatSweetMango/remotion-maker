# TM-120 — Placeholder fallback RCA + UX fix

## TL;DR

User-reported error `AI returned a placeholder/empty component three times — we substituted a default template` was traced to a **system-prompt construction bug**: `GENERATION_SYSTEM_PROMPT` (`src/lib/ai/prompts.ts`) embedded the literal skeleton markers `// ... all params`, `// animation logic`, `{/* component content */}`, and `// Complete TSX code here` inside its COMPONENT FORMAT and JSON-response examples. `gpt-4o-mini` was copying those markers verbatim into the `code` field — which `detectPlaceholderCode` (TM-51) correctly rejected, escalating to retry #1, retry #2, then the TM-100 3-strike fallback.

Live RCA (15-run × 5-tricky-prompt corpus) showed **66.7% retry-rate before fix; 0% after**. No prompts hit the 3-strike fallback during repro, but retry frequency at this magnitude meant the fallback was inevitable under load (and the user evidently hit it).

## RCA

### Hypotheses considered
| H | Hypothesis | Verdict |
|---|---|---|
| H1 | 3-tier retry ladder collapsed | REJECTED — code paths are correct (TM-51/TM-100 wiring fine) |
| H2 | `detectPlaceholderCode` false-positive | REJECTED — its regexes match real skeleton text |
| H3 | Empty-context post-clarify | PARTIAL — confirmed on extreme prompts (`안녕` + thin answers) but rare |
| H4 | TM-90 image-gen pipeline breakage | REJECTED — only triggers with `AI_MULTI_STEP=1`, not user's path |
| **H5** | **System-prompt skeleton tokens leak into LLM output** | **CONFIRMED — primary cause** |

### Evidence

Live corpus run (15 calls, `gpt-4o-mini`, OpenAI `temperature=0`):

```
[픽셀아트 곰돌이가 걷는 애니메이션] ×3 → retry #1 fired 1× (`// ... all params`)
[low-poly 3D dragon flying through clouds] ×3 → retry #1 fired 3× (skeleton x3)
[astronaut floating in space, minimalist line art] ×3 → retry #1 fired 3× (`// Complete TSX code here`)
[silhouette dancer ...neon background] ×3 → retry fired 0× (background-RAG hit gave concrete reference)
[실루엣 사람이 춤추는 ...] ×3 → retry #1 fired 3× (`// Complete TSX code here`)
```

Failure mode: model literally writes back the placeholder strings it saw in the system prompt's "COMPONENT FORMAT" example block, particularly on "tricky subject" prompts (living entities, narrative scenes) where the RAG reference is absent or weak.

### Why this is now the bottleneck
TM-51 (one retry) + TM-100 (extend to two + fallback) handled the symptom. But the underlying issue — that the example block in the system prompt contained tokens which a less-capable model would emit literally — was never addressed. As we widened the user-prompt corpus (TM-95 living-entity clarify, TM-90 image-gen), more requests routed to generate without a strong RAG reference, exposing the leak.

## Fix applied

### Primary fix — system-prompt hygiene (`src/lib/ai/prompts.ts`)

Replaced skeleton markers with concrete tokens:
- COMPONENT FORMAT example body now contains real params destructuring (`bgColor`, `accent`, `label`, `speed`), real animation math (`interpolate(...)`), and a real JSX body (`<div>...</div>`).
- Added an explicit **FORBIDDEN** clause naming the four leaked strings as never-allowed outputs.
- JSON-response example: `"code": "// Complete TSX code here"` → `"code": "const PARAMS = { /* real params */ } as const;\\n\\nexport const GeneratedAsset = (...) => { /* real animated JSX */ };"` plus an explicit "this is a marker, not a value" clause.

This keeps the system prompt cache-stable across the new wording (it's now the canonical form going forward; ADR-0003 cache key is set on first request after deploy).

### Secondary fix — UX (Fix-C, `src/lib/ai/generate.ts`)

Replaced `FALLBACK_WARNING` with action-oriented copy + 3 concrete success-pattern examples:
```
We couldn't quite generate from that prompt and substituted a default template.
Try adding a concrete subject + one of {palette, duration, data, style}.
Examples that work well:
  • "Bar chart top 5 products by revenue, purple gradient, 4s"
  • "픽셀아트 곰돌이가 걷는 애니메이션, 파스텔 톤"
  • "Fade in fade out logo intro, neon cyan, 2 seconds"
```

### Regression guards
Two new unit tests in `__tests__/lib/ai/generate.test.ts` under `describe('TM-120 system-prompt skeleton hygiene')`:
1. Asserts the COMPONENT FORMAT example body does NOT contain the bare skeleton markers.
2. Asserts the JSON example shows `"code": "const PARAMS..."` rather than `"code": "// Complete TSX code here"`.

These prevent the regression from re-entering via well-meaning prompt edits.

## Verification

### Before fix (v3 RCA, 15 runs)
- Retry-fired: **10 / 15 (66.7%)**
- Fallback: 0 / 15 (no 3-strike in this sample; user evidently hit one in production)
- Mean wall: ~14s (retry roundtrip cost)

### After fix (v3 RCA replay, same corpus, 15 runs)
- Retry-fired: **0 / 15 (0.0%)**
- Fallback: 0 / 15
- Mean wall: ~8s

`__tests__/lib/ai/generate.test.ts` — 33/33 pass, includes 2 new TM-120 guards.
