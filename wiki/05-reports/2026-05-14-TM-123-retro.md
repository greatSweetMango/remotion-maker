# TM-123 retro — `<Html5Audio>` src TypeError + AudioContext cascade

## User-blocking symptom

```
TypeError: The <Html5Audio> tag requires a string for `src`, but got 0 instead.
```

…followed by 100+ lines of `AudioContext encountered an error` in the studio
console. Triggered when LLM-generated code contained `<Audio src={PARAMS.someNumber}/>`
(or `<Audio>` with no `src` at all). The six recent assets
(ComicEffect / WaveText / ParticleField / FlowField / FluidBlobs / Constellation)
all flowed through the same generation path that exposed `Audio` as a global.

## Root cause — three layers compounded

1. **System prompt advertised `Audio`/`Video`/`OffthreadVideo` as available
   globals** (`src/lib/ai/prompts.ts:68`) without any restriction on `src`
   semantics. The model has no source-of-truth for an audio URL, so it
   either omits `src` or binds it to a `PARAMS.*` numeric.
2. **TM-116 evaluator destructured the full Remotion public surface**,
   including `Audio, Video, OffthreadVideo, IFrame, staticFile`
   (`src/lib/remotion/evaluator.ts:222`). This was originally added so
   gpt-4o multi-step scenes that mentioned `Series`/`Loop` would not throw
   `ReferenceError`. Side effect: every Remotion media component was
   silently in scope and would render at runtime.
3. **Sandbox deny list (`validateCode`) had no entry for media JSX tags.**
   The visual-only invariant existed in product spec but was never enforced
   in code, so a tag like `<Audio src={0}/>` passed validation cleanly and
   reached the `<Player>` tree, where Remotion's runtime check finally
   tripped — but only after spawning an `AudioContext` per frame.

## Fix (defense-in-depth, 3 layers)

### Layer 1 — `src/lib/remotion/sandbox.ts` (deny list)

Reject `<Audio>`, `<Video>`, `<OffthreadVideo>`, `<IFrame>` at validation
time. The pattern `/<\s*Audio\b/` matches the JSX open with optional
whitespace; the `\b` is between `o` and the following non-word char (`>`,
` `, `/`), so `<AudioBars>` / `<AudioVisualizer>` are NOT caught
(custom user components with names that just start with "Audio").

### Layer 2 — `src/lib/ai/prompts.ts` (LLM prompt)

- Removed `Audio, Video, OffthreadVideo` from the "AVAILABLE REMOTION
  GLOBALS" list.
- Added a `VISUAL-ONLY POLICY (TM-123 — MANDATORY)` block that explicitly
  forbids the four tags, explains the failure mode the user saw verbatim,
  and tells the model to translate audio-themed prompts into visual
  metaphors (pulsing shapes, waveform paths, equalizer bars).

### Layer 3 — `src/lib/remotion/evaluator.ts` (factory destructure)

Removed `Audio, Video, OffthreadVideo, IFrame` from the destructure. If a
tag somehow slips past the sandbox in the future, the factory body
ReferenceErrors at evaluation time instead of producing a broken
`<Html5Audio>` tree. NOTE: `Audio` and `Video` are also browser-level
constructors on `window`, so the global fallback still resolves them — the
sandbox is the sole defense for those two names; for `OffthreadVideo` /
`IFrame` (Remotion-specific) the evaluator gate is real.

### Layer 4 — `plugin/remotion-eval/src/validate.ts` (MCP server)

TM-115 deny-list-sync invariant: mirror the four new patterns in the
plugin's standalone validator so MCP callers (agents/Orchestrator) get
identical rejection behaviour.

## Existing user assets (already containing `<Audio>`)

Per task spec — no DB migration. Users re-generate affected assets. The
evaluator now surfaces a friendly Korean message
("코드를 해석할 수 없습니다 / 코드를 실행하는 중 오류가 발생했어요") with
a console log of `Forbidden: <Audio> (visual-only assets — TM-123)` for
dev triage.
