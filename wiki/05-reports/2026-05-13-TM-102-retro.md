# TM-102 retro — mcp-remotion-eval scaffold

## Scope

Scaffold a dedicated MCP server under `plugin/remotion-eval/` exposing a
single tool `validate_remotion_code(code)` that wraps the existing
in-app validation stack (`src/lib/remotion/sandbox.ts` deny-list +
`src/lib/remotion/transpiler.ts` sucrase pass + ADR-0002 PARAMS
structural checks). Intended consumers: the `remotion-validator`
subagent shipped in TM-99 and any future TeamLead pre-PR safety hook.

Out of scope (deliberate, per task brief): multi-tool surface
(`extract_params`, `dry_render_budget`), wiring into the actual subagent,
shared deny-list sync test with the app.

## What landed

- `plugin/remotion-eval/package.json` — isolated sub-package, sole runtime
  deps `@modelcontextprotocol/sdk@^1.0.4` + `sucrase@^3.35`.
- `plugin/remotion-eval/src/validate.ts` — pure-TS validation core
  (Node-safe, no React/DOM). Mirrors the deny-list as of TM-85 plus
  recursive-Promise-chain heuristic. Structural checks return
  `warnings[]` instead of hard failures so callers pick policy.
- `plugin/remotion-eval/src/server.ts` — MCP stdio server, single tool.
  Sets `isError: true` whenever `ok === false`.
- `plugin/remotion-eval/test/validate.test.ts` — 13 cases, `node:test` +
  `tsx`. Covers happy path, every deny-list category sampled, recursive
  Promise, invalid input, syntax errors, SCREAMING_CASE component regex
  guard (TM-58 gotcha).
- `plugin/remotion-eval/README.md` — `.mcp.json` registration snippet
  for both dist and source-mode runs.

## Verification

- `npm test` → 13/13 pass (`# pass 13 # fail 0`, 198 ms).
- `npm run build` → emits `dist/server.js` + `dist/validate.js` + d.ts.
- stdio smoke: `tools/list` JSON-RPC frame returns the
  `validate_remotion_code` schema correctly (one-shot pipe test).

## Decisions

- **Duplicated deny-list rather than importing `src/lib/remotion/sandbox.ts`.**
  Importing from the Next.js app graph would drag `react`, `lucide-react`,
  and the `@/` alias resolver into a process that needs to stay tiny.
  Trade-off: drift risk. Follow-up: sync test comparing the two arrays.
- **No real React eval in the MCP tool.** The in-app evaluator depends on
  React/DOM, so the MCP variant stops at transpile. This matches the
  intended use case (pre-PR / pre-prompt safety gate, not runtime preview).
- **Structural checks are warnings, not errors.** ADR-0002 is a project
  convention; some scratch/fixture code legitimately lacks `PARAMS`.
  Callers can promote warnings to errors per policy.
