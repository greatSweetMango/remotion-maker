# TM-114 — multi-step render fix

## TL;DR

TM-108 r3에서 multi-step 5/5 generate 성공·0/5 render(<Unknown> ErrorBoundary 100%)였던 원인은 gpt-4o가 `const { spring } = require('remotion');`를 multi-line 포맷으로 자주 emit → 기존 TM-111 sanitizer의 single-line `requireDecl` regex가 매치 실패 → bare-require fallback이 RHS만 `undefined`로 치환 → `const { spring } = undefined;` 잔재 → React render 시 destructure-of-undefined throw였다. multi-line 패턴을 새 regex로 잡고, 그 잔재(`const { … } = undefined|null;`)를 추가 sweep 하는 두 단계로 수정. 라이브 검증 5/5 PASS·5/5 evaluator render PASS.

## 무엇이 바뀌었나

- `src/lib/ai/pipeline.ts` `sanitizeForbiddenTokens`
  - `requireDecl` regex를 multi-line LHS(`{ … }`/`[ … ]`/identifier가 줄바꿈을 포함)도 매치하는 `requireDeclMulti`로 교체.
  - `const|let|var \{…\} = undefined|null;` 패턴을 통째로 strip 하는 `brokenDestructure` sweep 추가 (방어 레이어).
  - bare-require fallback 동작은 유지 (expression-position require는 여전히 `undefined`로 치환).
- `__tests__/lib/ai/pipeline.test.ts` — 3개 회귀 테스트 추가
  - multi-line 분해 require → 라인 통째 strip 검증
  - single-line 분해 require → strip + 잔여 코드 보존
  - 들여쓰기된 multi-line require → strip 검증
- `__tests__/benchmarks/tm-114-validate.ts` — TM-108 5 케이스 라이브 검증 + factory eval render 체크.

## 왜 / 배경

TM-108 r3 결과:
- Generate 5/5 (200), Render 0/5 — 모든 케이스가 `<Unknown>` ErrorBoundary로 떨어짐.
- 이전 분석: gpt-4o의 `const { spring } = require('remotion');` 패턴 → TM-111 sanitize → `const { spring } = undefined;` 변환 → render-time destructure-of-undefined throw.

근본 원인:
1. TM-111의 `requireDecl` 단일 라인 regex `^[ \t]*(?:const|let|var)\s+[^;\n]*=\s*require\s*\(...\)`는 LHS가 줄바꿈을 포함하면 매치 실패.
2. fallback `bareRequire`는 RHS의 `require(...)` 토큰만 `undefined`로 치환 → 분해 LHS와 함께 broken statement 잔존.
3. 잔존 `const { … } = undefined;`는 React가 컴포넌트 함수를 invoke 하는 순간 `Cannot destructure property 'X' of 'undefined'`를 던짐 → ErrorBoundary.

수정 전략:
- 1차 방어: declaration sweep을 multi-line LHS까지 확장 → broken artefact가 처음부터 생기지 않게.
- 2차 방어: 만에 하나 다른 경로(또는 LLM이 직접 emit)로 broken pattern이 들어와도 strip → 같은 사고 재발 차단.
- 분해 식별자(`interpolate`/`spring`/`Easing` 등)는 factory body 상단에서 runtime-injected globals로 이미 정의되므로, declaration 자체를 통째 제거해도 참조는 정상 동작.

## 영향

- 코드: `src/lib/ai/pipeline.ts` (+~25 lines), 테스트 3개 추가.
- 사용자: multi-step 파이프라인의 render 성공률 0/5 → 5/5 (TM-108 r3 케이스 기준).
