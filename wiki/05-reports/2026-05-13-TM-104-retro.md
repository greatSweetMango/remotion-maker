# TM-104 — Weekly dashboard roll-up

## 배경

지표가 여러 곳에 흩어져 있었다:

- **품질**: `wiki/05-reports/screenshots/TM-*/summary*.json` (TM-42 / TM-83 / TM-85 / TM-85-r2 / TM-76 …)
- **비용**: `.agent-state/spend.json` (롤업) + `.agent-state/spend-ledger.jsonl` (TM-101 도입, append-only)
- **처리량**: `git log` squash-merge `(#NN)` 패턴
- **에이전트 verdict**: `.agent-state/verdict-history.jsonl` (TM-101 정의, 아직 데이터 없음)

한 화면에 묶어보려면 매번 손으로 합산해야 했음. 야간 자동 STOP 가드 (TM-101) 가 들어가면서 "어제 야간이 어땠는지" 빠르게 보고 싶다는 수요가 생김.

## 변경

### 1. `scripts/dashboard/roll-up.mjs` (신규, ~310 lines, zero deps)

5개 수집기 + 1개 머지·렌더러:

| 수집기 | 입력 | 출력 |
|---|---|---|
| `collectMerges` | `git log --since=Nd` squash 패턴 | PR 수 + 평균 cadence (h/PR) |
| `collectBenchSummaries` | `wiki/05-reports/screenshots/*/summary*.json` | mode_match_pct, params_loss, unintended_pct, latency p50 (generate/edit) |
| `collectSpend` | `.agent-state/spend.json` + `spend-ledger.jsonl` | window total, by-kind, cumulative |
| `collectVerdicts` | `.agent-state/verdict-history.jsonl` | APPROVE/REQUEST_CHANGES/BLOCK, escalate rate |
| `aggregate` | 위 4개 | 한 객체 |
| `renderMarkdown` | aggregate | wiki 페이지 |

산출물:
- `wiki/02-dev/dashboard.md` (사람용)
- `.agent-state/dashboard.json` (기계용 — `.gitignore` 추가, 재생성)

플래그: `--dry-run`, `--json`, `--window-days=N`.

### 2. `scripts/launchd/com.easymake.dashboard-rollup-weekly.plist` (신규)

매주 일요일 23:50 KST 실행. meta-analysis (23:59) 보다 9분 먼저 돌아 dashboard 결과를 meta-analyzer 입력으로 활용 가능. `scripts/launchd/README.md` 등록 절차에 신규 plist 추가.

### 3. `.gitignore`

`.agent-state/dashboard.json`, `.agent-state/dashboard-logs/` 추가 (재생성 가능, 노이즈 회피).

```
$ node scripts/dashboard/roll-up.mjs

[roll-up] window=7d merges=43 benches=4 avg_mode_match=92.1
```

- ✅ verdict 0건 (history 미수집 — gracefully degrade)
- ✅ `--dry-run` 으로 마크다운 stdout 만, 파일 무변경
