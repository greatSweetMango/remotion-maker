# TM-101 — Night-mode STOP conditions + spend ledger

## 배경

기존 야간 자동 STOP 조건은 5개에 불과했고 모두 *catastrophic* 신호였다:

1. `.agent-state/STOP` file (수동)
2. spend.json 일일/주간 95% 초과
3. loop-count >100
4. openai_total_usd ≥ $18
5. AI QA final report 존재
6. task qa_iteration ≥5

문제: orchestrator 가 "**의미 없는 반복**" (개선 없는 bench loop, 폭주하는 비용, 좀비 worktree) 을 자동 감지하지 못해 사람이 아침에 STOP 을 찍어야 했다. TM-93 (visual-judge night-loop) 회고에서 가장 큰 비용 누수 케이스였음.

## 추가 5 신호

`scripts/orchestrator/stop-guard.mjs` (147 lines, ESM Node, zero deps) — orchestrate.md Step 7-1 매 iter 호출.

| 신호 | 트리거 | 동기 |
|---|---|---|
| `quality_plateau` | 최근 N=3 bench report `mode_match_pct` drift <1pp | 더 돌려도 품질 안 오름 → 야간 자원 낭비 차단 |
| `error_rate_spike` | 최근 5 verdict 중 BLOCK/REQUEST_CHANGES ≥60% | 오케스트레이터/agent 자체 문제 → 폭주 차단 |
| `worktree_leak` | `git worktree list` ≥5 | concurrency-limit 무시 누적 → orphan cleanup 실패 감지 |
| `stale_lock` | branch-locks.json started_at >6h | TeamLead crash 좀비 task — TM-55 race 사례 |
| `cost_burst` | spend-ledger.jsonl 최근 60min ≥$3 | 정상 야간 비용의 ~5x — 폭주 조기 차단 |

신호 발견 시:
- 각 신호별 `[stop-guard] <signal>: <reason>` 라인 transcript 출력
- `.agent-state/STOP` 파일 작성 (기존 STOP 존재 시 보존 — 원본 reason 우선)
- exit 42 → orchestrate.md Step 7-1 이 즉시 `exit`

모든 임계는 env 로 override (`STOP_*`) — tests/staging 에서 조정 가능.

## spend-ledger.jsonl

기존 `spend.json` 은 단일 누적값(`openai_total_usd`)만 가짐 → 시간대 / task / model breakdown 불가능 → cost_burst 같은 슬라이딩 윈도우 분석 불가.

신규 `.agent-state/spend-ledger.jsonl` (append-only):
```json
{ "ts": "ISO-8601", "task_id": "TM-X", "model": "gpt-4o-mini",
  "tokens_in": N, "tokens_out": N, "cost_usd": F, "kind": "openai|anthropic|other" }
```

- `spend.json` 누적값은 그대로 유지 (canonical totals)
- ledger 는 **분석 전용 데이터 소스** — TM-104 dashboard 가 활용 예정
- 생산자(쓰기): PostToolUse hook (다음 작업) — 이 PR 은 ledger 파일 *포맷 정의 + 컨슈머(stop-guard)* 만 구현
- 컨슈머(읽기): stop-guard `checkCostBurst`
