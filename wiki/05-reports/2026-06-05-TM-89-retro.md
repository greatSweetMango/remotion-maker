# TM-89 — image-gen asset 영구 캐시 (ADR-0022 follow-up)

> `hash(prompt+style+size) → cacheKey` 영구 캐시 추상화. 적중 시 image-gen LLM 호출 skip → 비용 0 기록. 기본 FS 백엔드(credential 불필요) + R2(S3-호환) 어댑터, 신규 의존성 없음.

## 한 줄 요약

TM-84/TM-90 의 임시 local-FS 캐시(serverless redeploy 시 소멸)를 **pluggable 영구 캐시 추상화**로 마이그레이션했다. `AssetCache.get/put` 인터페이스 + 2개 구현체(FS 기본, R2). spend hook 연동으로 캐시 hit 시 cost 0, miss 시 flat image 가격 기록.

## 설계 결정

- **신규 의존성 회피**: R2 는 S3-호환이므로 `@aws-sdk/client-s3` 대신 Node 22 내장 `crypto`(SigV4) + 전역 `fetch` 로 직접 구현. SOP 의 "새 의존성 추가 시 escalate" 차단 항목을 우회 — ADR-0022 도 "신규 의존성: 없음" 명시. ADR-0013 storage abstraction 의 lazy-import / env-gate 패턴 그대로 계승.
- **behavior 변경 범위 = 캐시 hit 시 image-gen skip 뿐** (ADR-0022 제약 준수). 기존 result 필드(`cached/hash/imageUrl/costUsd/latencyMs/matchedToken`) 전부 보존, `cacheProvider` 만 additive(optional).
- **충돌 회피(TM-187)**: 모든 캐시 로직을 `asset-cache/` 신규 모듈 + `asset-gen-stage.ts` 내부에 격리. `pipeline.ts`/`generate.ts` 미수정 → rebase-friendly.
- **spend 인코딩**: gpt-image-1 은 per-image 과금(토큰 없음). `costOpenAI = tokens*in/1e6` 산식에 맞춰 `in:1`, `prompt_tokens = costUsd*1e6` 로 정확히 costUsd 산출.

## Escalation — R2 실연동 (blocking)

이 환경엔 R2 credential 이 없어 **실제 버킷 연결·배포는 미수행**. R2 어댑터는 mock fetch 로만 검증됨. 운영 전환에 필요:

- env: `R2_BUCKET_NAME`, `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY` (옵션: `R2_PUBLIC_BASE_URL` CDN/public domain, `R2_KEY_PREFIX`).
- 버킷 생성 + public access 정책(또는 CDN front) + 라이브 GET/PUT 1건 e2e 검증(야간 키-루프).
- env 없으면 자동으로 FS fallback 이라 안전 — 배포가 깨지지 않음.
