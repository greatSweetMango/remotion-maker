# TM-206 — TeamLead Phase 체크포인트 / 재개

> watchdog/overload kill 후 TeamLead 재디스패치 시 Phase A 부터 재시작하지 않고
> **마지막 완료 Phase 다음부터 재개**한다. TM-205 progress-ledger(stall 감지)와
> 공존하며 stall **후 진척 보존**을 더해 한 쌍을 완성. 이번 세션 TM-184 가 2회
> stall 로 작업유실 직전까지 간 문제 직결.

## 한 줄 요약

TeamLead Phase A→F 를 **체크포인트 경계**로 만들었다. 각 Phase 종료 시
`.agent-state/checkpoint.json`(worktree-local, gitignore)에 last-completed-phase
high-water-mark + 누적 artifacts(pr_url/commit/adr 등)를 기록하고, 첫 turn 에
그 파일을 읽어 마지막 완료 Phase 다음부터 재개(이미 만든 PR/커밋/산출물 재사용,
중복 생성 금지). 순수 additive — 콜드 스타트 무영향.

## TM-205 와의 공존 (핵심 제약)

TM-205 가 막 추가한 progress-ledger emit 지시를 **덮어쓰지 않고 그 위에 얹었다**.
두 훅은 같은 Phase 경계를 공유하되 역할이 분리된다:

- progress-ledger(`append-progress.sh`) → append-only, **Orchestrator** 가 읽는
  in-flight health 신호(`stop-guard.mjs` `phase_loop`).
- checkpoint(`write-checkpoint.sh`) → 덮어쓰기 1파일, **TeamLead 자신** 이 재개에
  쓰는 worktree-local durable 상태.

각 Phase 종료 emit 라인은 그대로 두고, 그 **직후** checkpoint write 한 줄을 추가했다.

## 재개 시나리오 (멱등성)

```
[정상]   cold start: checkpoint.json 없음 → Phase A 부터 정상 실행
[kill]   Phase D 완료(PR 생성) 직후 checkpoint write → 그 순간 kill
[resume] Orchestrator 재디스패치(resume=true) → 새 TeamLead 첫 turn:
         set-current-task → checkpoint.json 읽음 → last_completed_phase=D
         → Phase E 부터 재개. artifacts.pr_url 존재 → gh pr create 재호출 안 함
         (기존 PR 재사용). artifacts.adr_path 존재 → ADR 재작성 안 함.
```

- **high-water-mark 의미론**: checkpoint 는 Phase 가 *완전히 끝난 직후에만* 기록되므로,
  Phase 중간 kill 은 그 Phase 를 반영하지 않아 재개 시 처음부터 재실행(부분 작업 폐기 —
  안전 측 default).
- **부작용 멱등성**: PR/커밋처럼 외부 부작용이 있는 Phase 가 재실행돼도 Phase D 의
  pre-PR dup 가드(`pre-pr.sh` rc==10 open PR → create 금지)와 git 자연 멱등성(같은
  커밋 재push = no-op)이 중복을 흡수한다.

## 검증

- `write-checkpoint.sh` 스모크: Phase A→D artifacts 머지 확인, `TM-206`/`206` 정규화,
  무인자 artifacts 기본 `{}`, 잘못된 JSON/배열 artifacts rc=2(파일 미생성), usage rc=2,
  `bash -n` 통과.
- `git check-ignore .agent-state/checkpoint.json` → ignored.
- 콜드 스타트 경로 무변경(additive) 확인.

## 배운 점 / 후속

- TM-205(detect) + TM-206(resume)로 Magentic-One detect→replan 에 durable resume 추가.
- `write-checkpoint.sh` 의 artifacts 머지는 node 의존 — node 부재 CI 에서는 verbatim
  폴백(prior-merge 없음). 현재 워크플로는 node 상시 가용이라 무영향이나, 폴백 경로는
  best-effort 임을 명시.
- 향후: replan_count 와 checkpoint 의 last_completed_phase 를 Orchestrator 가
  cross-check 해 "Phase F 도달했는데 또 replan" 같은 모순 상태를 조기 escalate 가능
  (본 task 범위 밖).
