# TM-128 — Sandbox `<Audio>` structural allow-list (ADR-0026 §2)

## Summary

Reintroduces `<Audio>` to LLM-generated Remotion code under a strict shape
constraint: only `<Audio src={staticFile("audio/<slug>.mp3")} />` where
`<slug>` matches the catalogue regex `^[a-z0-9-]+\.mp3$` is allowed; every
other shape (numeric / variable / template-string / external URL / path
traversal / wrong extension / mixed) still trips the TM-123 deny rule.
`<Video>` / `<OffthreadVideo>` / `<IFrame>` remain unconditionally denied.

## What changed

- `src/lib/remotion/sandbox.ts` — added `isAudioAllowListed(code)` regex-shape
  matcher; `validateCode` now skips the `<Audio>` deny entry when **every**
  `<Audio` token in the source matches the allow shape. Deny entry stays in
  `FORBIDDEN_PATTERNS` so the TM-115 sync test continues to pass.
- `plugin/remotion-eval/src/validate.ts` — mirrored allow-list (same regex,
  same skip logic).
- `__tests__/lib/remotion/sandbox.test.ts` — new `TM-128 <Audio> structural
  allow-list` suite: 4 positive + 9 negative cases.
- `plugin/remotion-eval/test/validate.test.ts` — 7 mirror cases.

## Validation

- `__tests__/lib/remotion/*` — **128/128 pass** (sandbox + denylist-sync +
  fuzz + evaluator + evaluator-fuzz).
- `npm --prefix plugin/remotion-eval test` — **32/32 pass**.
- TM-115 deny-list set-equality test still green (deny entry preserved in
  both files; allow-list is a sibling check).
- TM-123 negative cases unchanged (numeric / external URL / variable src
  still rejected with `Forbidden: <Audio>` label).

## Design notes

- Used a regex-shape matcher rather than a real AST walker to stay
  consistent with the existing `FORBIDDEN_PATTERNS` strategy (cheap, runs
  on every edit). The pattern is intentionally narrow:
  `/<\s*Audio\b[^<>]*\bsrc\s*=\s*\{\s*staticFile\s*\(\s*['"]audio\/[a-z0-9-]+\.mp3['"]\s*\)\s*\}[^<>]*\/?\s*>/`.
  Catalogue-existence (does the slug map to a real `MANIFEST.json` track?)
  is intentionally out of scope here — that check belongs at customize/
  render time (TM-130), where users can select a track. A static lookup
  here would couple LLM validation to a JSON file and force re-validation
  on manifest edits.
- `<Audio>` deny entry preserved in `FORBIDDEN_PATTERNS` arrays so the
  `denylist-sync.test.ts` set-equality check stays trivial. The skip is
  driven by a runtime label-prefix check in `validateCode`.
- Mixed files (one allow-listed tag + one variant) reject — the variant
  fails the shape check and `isAudioAllowListed` returns false for the
  whole file, restoring the deny rule.

## Follow-ups

- TM-129 (prompt update): instruct the LLM to emit the allow-list shape
  with a closed enum of catalogue slugs.
- TM-130 (customize UI): BGM track picker bound to `MANIFEST.json`.
- TM-131 (Lambda render): bundle `public/audio/` and verify determinism.
- Consider an evaluator-time check that verifies the slug actually exists
  in `MANIFEST.json` (would catch slug typos before render).
