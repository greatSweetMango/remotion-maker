# TM-87 — User asset management

## Context

User reported: "내가 만든 프로젝트를 내가 관리할 수 있도록 데이터를 관리하는
시스템이 없는 것도 문제" — the framing implied no management UX existed.

Audit found a **partial** management surface already shipped under earlier
tasks:

| Capability | Status before TM-87 | Source |
|---|---|---|
| `/dashboard` list with usage stats | shipped | `src/app/dashboard/page.tsx` |
| Search / sort / date filter / pagination | shipped | `AssetGrid.tsx` + `GET /api/assets` |
| Soft-delete to trash | shipped | `DELETE /api/asset/[id]` (TM-18) |
| Trash restore + 30-day TTL | shipped | `/trash`, `/api/trash`, `/api/trash/[id]` |
| Fork from public share | shipped | `POST /api/asset/fork` |
| **Rename** | **missing** | — |
| **Owner-side duplicate** | **missing** | — |

Real gap: no way to rename your own animation, no way to clone one of your own
without going through the public-share fork detour. TM-87 closes exactly those
two.

## Scope decision (MVP)

In:
- `PATCH /api/asset/[id]` — title-only rename, owner-only, trim + length-cap.
- `POST /api/asset/[id]/duplicate` — owner clone (distinct from `/fork`),
  carries code/params/dimensions, drops sharing + lineage.
- Dashboard `AssetCard` — replace single trash button with a `MoreVertical`
  dropdown: Rename / Duplicate / Move to Trash. Rename uses an inline shadcn
  `Dialog` (mobile-friendly vs `window.prompt`).

Deferred (v2 ticket recommended):
- Search inside body (currently title-only).
- Tag / folder organization.
- Bulk select / multi-delete.
- Custom thumbnail (would require Prisma migration → BLOCKed by policy).

## Design notes / decisions

1. **Duplicate vs fork**. Kept them as separate endpoints. `/fork` takes a
   `publicSlug` and records `sourceAssetId` (lineage of who-forked-whom on
   public shares). `/duplicate` takes an asset id, is owner-only, records no
   lineage, drops `publicSlug`/`sharedAt`. Different invariants → different
   routes. Single-endpoint overload would have forced ambiguous body shapes.

2. **No version-history clone on duplicate**. `AssetVersion` rows are NOT
   copied; the copy starts with a fresh edit log. Cheaper, and matches user
   mental model — "I want a starting point, not someone else's edit history."

3. **PATCH refuses soft-deleted assets** (404 not 410). Prevents accidental
   silent resurrection from trash via a rename. Restore must go through
   `/trash` explicitly.

4. **No `maxAssets` cap on duplicate**. Audited `TIER_LIMITS` — the launch
   quota model bounds `monthlyGenerations` (LLM cost) and `editsPerAsset`,
   not storage row count. Duplicate is pure DB clone (no LLM call) so it's
   unmetered, matching the existing fork endpoint's posture.

5. **Title suffix idempotency**: `"X (copy)"` → `"X (copy)"` (no chain). If
   the user wants more than one copy, the second one keeps the same name —
   acceptable since the dashboard sorts by `updatedAt` and titles are not
   unique. Avoids ugly `"X (copy) (copy) (copy)"` chains.

## Lessons

- **Audit before assuming "X is missing"**: user framing was correct that
  management was incomplete, but the gap was narrower than implied. Two
  endpoints + one component edit closed it, not a new dashboard.
- **Owner-only routes need both ownership check AND deletedAt filter** — a
  bare ownership check would let renames quietly modify trashed rows that
  the dashboard never shows.
