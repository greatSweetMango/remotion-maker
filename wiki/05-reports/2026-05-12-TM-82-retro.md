# TM-82 retro — 캐릭터/장면 렌더링 capability ADR

## TL;DR

PR #127에서 드러난 character/scene 렌더 capability gap에 대해 옵션 A(SVG lib) / B(image-gen) / C(generative SVG) 를 비교, **1차 B (gpt-image-1) + 2차 A 보강 hybrid** 추천하는 ADR 초안 작성. 코드 변경 0건. spike PoC는 별도 follow-up으로 분리.

## 왜 / 배경

PR #127(b2f955c)은 "곰돌이 캐릭터가 초원을 걸어가는 10초 애니메이션" 같은 프롬프트에서 모델이 system-prompt skeleton을 그대로 echo 하는 실패 모드를 잡고 clarify로 라우팅하도록 수정했다. 그러나 clarify 응답을 받아도 **곰의 형상을 충실히 그릴 능력**이 파이프라인에 없어 default counter로 fallback. 35개 모션그래픽 템플릿엔 캐릭터 0개. 코드만으로는 해결 불가 → asset/이미지 통합이 필요.

## 영향

- **결정 영향**: ADR-0001(편집≠렌더), ADR-0003(캐싱)은 유지 가능. image-gen은 첫 generate 1회 한정 + R2 캐시로 편집 단계는 LLM only 유지.
- **비용 영향**: 첫 generate $0.005 → $0.045 (9×), but 캐시 적중 시 편집은 $0.005 유지. Pro $12 마진은 적중률 ≥ 70% 가정 시 절반 이상 보존.
- **UX 영향**: 첫 generate에 5–15s latency 추가 — progressive UI 필요.
- **신규 의존성**: 없음 (OpenAI SDK + R2 모두 기존 사용).
