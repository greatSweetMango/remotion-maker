# TM-145 — Lottie prompt catalogue enum + emission rule

## TL;DR

`LOTTIE_CATALOG_SLUGS` 닫힌 enum을 `manifest-types.ts`에 추가하고, `GENERATION_SYSTEM_PROMPT`에 **LOTTIE CATALOGUE POLICY** 섹션을 신설했다. 8개 슬러그(bear-walk / cat-walk / dog-run / cat-idle / person-dance / kid-jump / bird-fly / sky-clouds)와 한국어 키워드 매핑(곰/강아지/고양이/사람/새 등)을 프롬프트에 명시. Lottie ↔ image-gen 동시 가능 시 deterministic·$0인 Lottie 우선, 카탈로그 외 entity(용/공룡 등)만 image-gen fallback. CHARACTER 섹션도 cross-reference 갱신. 11개 단위 테스트 신규 + 기존 audio/categories 정책 회귀 통과(34 passed).

## 무엇이 바뀌었나

- **신규 enum**: `src/lib/lottie/manifest-types.ts` — `LottieCatalogSlug` union + `LOTTIE_CATALOG_SLUGS: readonly LottieCatalogSlug[]` (AUDIO_MOODS 패턴 1:1 미러).
- **시스템 프롬프트 갱신**: `src/lib/ai/prompts.ts`
  - 상단 import + `LOTTIE_CATALOGUE_LIST` 보간 상수.
  - AVAILABLE REMOTION GLOBALS에 `CatalogueLottie (TM-140 wrapper ...)` 추가.
  - 기존 audio policy 직후 / ICONS 직전에 **LOTTIE CATALOGUE POLICY** 블록 신설(슬러그 enum verbatim, 한·영 키워드 매핑 hint, decision rule, lottieAsset PARAMS + 3-layer scene 예제).
  - CHARACTER 섹션 헤더에 `<CatalogueLottie>` 우선 사용 cross-reference 삽입.
- **테스트**: `__tests__/lib/ai/prompts-lottie-policy.test.ts` (11 cases) — 슬러그 verbatim, 한국어 키워드, decision rule, audio/character 회귀, clarify-prompt 상속까지 커버.

## 왜 / 배경

ADR-0027 §2 후속. TM-140이 `<CatalogueLottie>` 랩퍼 + sandbox deny + 8-asset 카탈로그(TM-144)를 깔았지만 LLM이 카탈로그를 **알지 못함** → "곰돌이 walking" 같은 표준 living-entity 프롬프트는 여전히 vector / image-gen 경로로만 흘러감. TM-129 audio 패턴(`AUDIO_MOODS` enum + 시스템 프롬프트 verbatim 삽입)을 1:1 미러하면 LLM이 deterministic 슬러그를 직접 선택하게 됨.

추가로 한국어 사용 비중이 높은 사용자 베이스 특성상 곰/강아지/고양이/사람/새 → 슬러그 매핑을 하드코딩해 prompt-time disambiguation 비용을 줄임.

## ADR-0003 cache invalidation 영향

- `GENERATION_SYSTEM_PROMPT` 본문이 길어졌다(약 +90 lines). 다음 edit 호출에서 ephemeral cache key가 한 번 miss → 재캐싱.
- 의도된 invalidation: stale cache는 새 카탈로그를 추천하지 못하므로 1-회 cache miss를 감수.
- 슬러그 enum 자체가 프롬프트에 보간되므로 향후 카탈로그 확장(TM-149+) 시에도 자동으로 cache invalidation 발생 — silent regression 차단.
