# TM-205 — progress ledger + stall detector (orchestrator-v2 #1)

## 목표

post-hoc verdict 로그(`verdict-history.jsonl`)에만 의존하던 안전 가드를 **in-flight health** 로 보강. TeamLead 가 Phase 별 progress-ledger 1줄을 append → `stop-guard.mjs` 가 막힌(stalled) task 를 거의 실시간으로 감지·재계획.

## 한 일

1. **`scripts/orchestrator/append-progress.sh`** (신규) — `.agent-state/progress-ledger.jsonl` 에 `{ts,task_id,phase,progress_made,in_loop,satisfied,next_action}` JSONL append. `append-verdict.sh` 미러, `task-queue.sh`/`branch-locks.sh` 의 flock→mkdir mutex 패턴 재사용(별도 lock anchor). bool 0|1 validation, free-text JSON-escape, task_id 정규화(TM-N|N).
2. **`stop-guard.mjs` 신호 6 `phase_loop`** (additive) — task_id 별 newest-first 로 선행 `progress_made=0` 연속 run 을 세어 `STOP_PHASE_LOOP_CONSEC`(기본 2) 이상이면 발화. `runChecks()` 끝에 `checkPhaseLoop` 추가, 기존 5신호 불변.
3. **`prompts/team-lead.md`** — Phase A~F 종료 emit 1줄 지시 + "정직하게 0 기록" 가드.
4. **`.claude/commands/orchestrate.md` Step 7** — `phase_loop` 만 떴을 때 전역 STOP 대신 해당 task reset+replan(lock/worktree 회수 → pending → replan_count++ → REPLAN row 로 run 리셋) → 다음 iter 재디스패치. replan_count≥3 → blocked+STOP. **Step 3/Step 5 미접촉**(TM-207/TM-208 충돌 회피).
5. **ADR** `wiki/01-pm/decisions/0033-progress-ledger.md` (토큰 `ADR-0033`).
