# TM-193 — generate↔pipeline 순환 의존 해소

## TL;DR

TM-183 madge가 검출한 유일한 순환 의존(`src/lib/ai/generate.ts` ↔ `src/lib/ai/pipeline.ts`)을 **콜백 주입(dependency injection)** 으로 단방향화했다. behavior-preserving, public import surface 무변경. `madge --circular`와 repo의 `npm run check:circular`(depcruise) 모두 클린, 관련 테스트 138건 전부 그린.

## 무엇이 바뀌었나

- `pipeline.ts`의 TM-111 single-shot 폴백이 `await import('./generate')` 로 `generateAsset` 를 동적 임포트하던 부분을 제거.
- 대신 `MultiStepOptions.singleShotFallback` 콜백을 추가하고, dispatcher인 `generate.ts::generateAsset` 가 자기 자신(`generateAsset`)을 폴백으로 주입.
- 의존 방향이 양방향(`generate ↔ pipeline`)에서 단방향(`generate → pipeline`)으로 정리됨.
- `MultiStepOptions` 에 `singleShotFallback?: SingleShotFallback` 필드 + `SingleShotFallback` 타입 export 추가.
- TM-111 폴백 테스트(`pipeline.test.ts:852`)를 `jest.doMock('@/lib/ai/generate')` 동적 임포트 모킹 → `opts.singleShotFallback` 주입 방식으로 갱신.

## 왜 / 배경

- 두 파일은 서로의 export를 **동적 import** 로 양방향 참조 중이었다:
  - `generate.ts:725` → `import('./pipeline')` 로 multi-step 디스패치 (위로 호출).
  - `pipeline.ts:1506` → `import('./generate')` 로 single-shot 폴백 (아래로 호출).
- madge는 동적 import도 그래프 엣지로 카운트하므로 순환으로 보고. CI `Lint — circular dependencies`(check-circular.yml) 관점에서 해소 필요.
- 자연스러운 레이어링은 `pipeline(상위 오케스트레이터) → generate(하위 single-shot 코어)`. 따라서 끊을 엣지는 `pipeline → generate`. 함수 본문을 대규모로 이동하면 TM-184(같은 파일에 liveness 게이트 hook 동시 추가)와 충돌 위험이 크므로, **순환을 끊는 최소 추출 = 콜백 주입** 을 선택.

## 영향

- 코드 / 시스템 영향: 런타임 동작 동일. 폴백은 여전히 `generateAsset` 를 `AI_MULTI_STEP=0` 강제 상태에서 호출 → single-shot 경로로 라우팅(기존과 동일). 주입 콜백이 없는 직접 호출자(테스트/벤치)가 폴백 경로를 치면 원본 pipeline 에러를 re-throw(silent drop 방지).
- Public import surface: `generateAsset`, `generateAssetMultiStepAsApiResponse` 등 외부 export 전부 유지. 호출부(`route.ts`, `jobs/process/route.ts`) 무변경.
- 비용/성능 영향: 없음(임포트 구조만 재배치).
