# TM-209 — tasks.json 동시쓰기 race 제거 (단일-writer mutex)

## 배경

이번 세션에서 raw `python` write 와 `task-master` MCP write 가 직렬화 없이 `.taskmaster/tasks/tasks.json` 에 동시 접근 → int/str id 혼동 + lost-update race → "tasks.json 손상" 가짜 신호. branch-locks.json 은 이미 mutex 보호 중이었으나 tasks.json 만 무방비였다.

## 한 일

- **신규 `scripts/lib/task-queue.sh`** — `branch-locks.sh` 의 flock(Linux/CI) / `mkdir`(mac 폴백) mutex 패턴 재사용. 별도 anchor `.agent-state/.tasks.lock`(+`.tasks.mutex.d`) 로 branch-locks 와 독립 → 동시 보유 가능, 기존 동작 비회귀.
  - `task_queue_set_status <id> <status>` (`TM-209`/`209` 모두 정규화), `task_queue_append_task <json>`(중복 id 거부), `task_queue_with_lock <cmd...>`.
  - **id 항상 문자열 정규화** (`.id |= tostring` at write chokepoint).
  - tagged-format 인지: `state.json.currentTag` → `master` → 단일 태그 키 → legacy `.tasks`.
- **`scripts/orchestrator/promote-spawned.sh` 전환** — `task-master add-task` 배치 전체를 `task_queue_with_lock` 하에 실행. 기존 private `task-master.lock`(mac 에선 flock 부재 시 무락이던 갭) → 공유 `.tasks.lock` + mkdir 폴백으로 교체. 폴백 jq 스캔도 tagged-format 인지로 수정.
- **flock 경로 버그 회피** — `flock -c "<string>"` 는 sh 재-exec 으로 bash 함수가 소실됨. fd-form `flock 8` + 함수 직접 호출로 변경(원형 branch-locks 의 `-c` 패턴이 가진 잠재 버그를 task-queue 에선 회피).
- **문서** — `prompts/team-lead.md` 에 "TeamLead tasks.json 직접 write 금지" 1문단, `.claude/commands/orchestrate.md` Step 5 직렬-적용 주석 2줄(충돌 회피 위해 최소).
- **ADR** — `0032-tasks-json-single-writer.md` (token `ADR-0032`).
